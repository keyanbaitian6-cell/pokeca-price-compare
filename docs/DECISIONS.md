## 2026-08-18: 未開封BOXの名寄せ方針

店舗ごとの表記差を吸収するため、商品名にはUnicode NFKC正規化を適用してから不要語を除去します。
部分一致による削りすぎを防ぐため、長い語から順に処理します。

主な除去対象は次のとおりです。

- 商品接頭辞: `ポケモンカードゲーム`、`ポケモンカード`
- シリーズ名: `スカーレット&バイオレット`、`ソード&シールド`、`サン&ムーン`、`ダイヤモンド&パール`、`XY BREAK`、`XY`
- 販売上の注記: `着払い対象外商品`、`着払い対象外`
- 状態語: シュリンクの有無、ぺりぺりの有無、`ボックス`、`BOX`
- 品番: `M3`、`M5`、`M1L`など。ただし独立した品番として現れた場合だけ除去する

`ポケモンカード151`は`151`へ寄せますが、`151 カードファイルセット`は別商品として維持します。
また、`ポケモンカードe 基本 海からの風`の`e`はシリーズ識別に必要なので削除しません。
`シャイニートレジャー`は`シャイニートレジャーex`へ寄せる既存の別名処理を維持します。

状態は商品名とは別に保持し、利用者向けシートでは
`シュリンク有`、`シュリンク無`、`ぺりぺり無`、`状態不明`、`未開封（状態不明）`と日本語表示します。
片方の店舗だけ状態不明の場合は比較を許可し、「注意」列に`状態推定`と表示します
（2026-08-18に`一部店舗で状態不明`から変更。後述の比較タブ再設計を参照）。
両方の店舗に実状態がある場合、シュリンク有とシュリンク無は別商品として扱います。

## 2026-08-18: 毎日17時の自動更新と手動更新の併用

価格表はGitHub Actionsのスケジュール（`0 8 * * *` UTC ＝ 毎日17:00 JST）で1日1回自動更新します。
それ以外のタイミングで即座に更新したい場合は、
[Vercelの手動更新ページ](https://pokeca-price-update.vercel.app)から手動更新できます。
Googleシートの「サマリー」にも同じページへのリンクを置きます。

手動更新ページは合言葉を検証した後、GitHub Actionsの`manual-update.yml`を`main`ブランチで起動します。
連続実行を避けるため、直近の実行開始から5分間、または更新処理の実行中は新しい起動を受け付けません。

合言葉の平文、合言葉ハッシュ、GitHubトークンはフロントエンドとGitリポジトリに保存しません。
合言葉ハッシュとGitHubトークンはVercelのSensitive環境変数として保存します。
この判断記録にも合言葉の値は残しません。

### セキュリティ上の残存リスクを受容する

この更新ページは公開サービスではなく、URLを公開せず、利用者1名が約3日に1回使用する前提です。
通常運用は月約10回で、実測約2分のジョブをGitHubの分単位切り上げで1回3分と見積もると、
GitHub Actionsは約30分/月です。

2026-08-18の調査では、runtoへの1回の更新は一覧9ページと商品詳細32ページの計41 GETでした。
月10回なら約410 GET/月です。買取ソムリエは2カテゴリを開くため、最低20ページ遷移/月に
JavaScriptなどのサブリクエストが加わります。この頻度なら個人利用として許容できる負荷と判断しました。

現在の5分制限は、正しい合言葉による実行後の連続起動を抑止するものです。
失敗した合言葉の試行回数制限や、複数リクエストを原子的に処理する分散ロックは実装していません。
非公開URL、単独利用、低頻度という運用条件を前提に、この残存リスクを認識したうえで受容します。
URLを共有する、利用者を増やす、更新頻度を上げる、または公開サービスへ変更する場合は、
合言葉の強化、失敗回数制限、原子的なレート制限を再検討します。

## 2026-08-18: 比較タブは2サイト以上の行だけにする

比較タブ147行のうち75行が1サイトにしか掲載がなく、価格差が空欄のまま並んでいました。
比較表の半分が比較できない行で埋まっていたため、掲載店が1サイトだけの行は
新しい「単独掲載」タブ（商品名／状態／掲載店／買取価格、買取価格の降順）へ分離します。

分離は `google_output.py` の表示直前で行い、`compare.py` の `build_box_comparison` は
これまでどおり全行を返します。`data/box_comparison.csv` の内容も変わりません。
名寄せ（`normalize.py`）には一切手を入れていません。

比較タブの列は次の10列です。

`商品名／状態／最高値／最高値の店／差率／差額／コレクト／runto／買取ソムリエ／注意`

判断の根拠は次のとおりです。

- 末尾3列にあった各サイトの元商品名は削除しました。runtoの商品名は平均38文字・最大81文字あり、
  同じ情報は「全取得」タブに残るため、比較タブでは冗長でした。
- 差率（価格差÷最高買取価格）を追加し、並び順を差率の降順にしました。円だけでは
  イーブイヒーローズの5,000円差（3.8%）とステラミラクルの3,800円差（32%）が同列に見えます。
  店選びで差がつく商品を上に出すのが比較タブの目的です。
- 「最高値の店」は同額が複数ある場合に中黒で連結し、3店すべて同額なら`3店同額`と表示します。
- 「注意」列は狭いため、表示を`一部店舗で状態不明`から`状態推定`へ短縮しました。
  意味は変わらず、`condition_inferred` フラグの内部表現も変えていません。
- 旧裏BOX（runtoの`第1弾 拡張パック`1,300万円など8桁の17行）はすべて1サイトのみでした。
  単独掲載タブへ分離した結果、比較タブの最高額は260,000円になり、桁の差による見づらさは解消しました。
  これらの価格は桁ミスではなく実際の相場なので、値は補正していません。

書式はSheets APIの`batch_update`へまとめて送ります。`worksheet.clear()`は値だけを消して書式を残すため、
毎回シート全体の書式をリセットしてから当て直します。最高値と一致する価格セルは緑、
差率5%以上のセルは赤太字、注意のあるセルは薄黄、ヘッダーは濃紺＋白太字です。

## 2026-08-18: 差額にも独立した強調を持たせる

差率だけで並べると、高額帯の商品が沈みます。イーブイヒーローズは最高値135,000円で差額5,000円、
差率3.7%です。5%未満なので赤太字にならず順位も下がりますが、実際に手に入る差額は
1位のステラミラクル（3,800円）より大きい。率で並べる判断が高額帯で裏目に出ていました。

そこで差額列にも独立した閾値を持たせ、3,000円以上を金色（BF8F00）の太字にします。
差率5%以上の赤太字（C00000）とは列も色も分け、率の印と額の印が混ざらないようにしました。

閾値3,000円は実データから決めました。2026-08-18の73行では、差率5%以上が29行、
差額3,000円以上が5行、両方に該当するのが4行です。金色だけが付くのは
イーブイヒーローズ1行で、拾いたかった行がちょうど拾えます。5,000円にすると2行になり、
イーブイヒーローズは拾えますが余白が大きすぎます。

比較タブは列を絞って読みやすくしたので、説明を書く幅がありません。差率・差額・注意の
ヘッダーにはセルのノートで定義を添えます（`updateCells` の `note` として同じ
`batch_update` に相乗りさせるので、APIコールは増えません）。

### 却下した案

- 「掲載店数」列の追加。3つの価格列の空欄でもう分かるため、列を減らした目的に反します。
- 条件付き書式への移行。ルールは実行のたびに累積するので毎回削除と再追加が必要で、
  APIコールは今も1回なので削減効果がありません。行数が数倍になったら再検討します。
- 差率の分母を最安値へ変更。差率は最高値÷最安値の単調関数なので、分母をどちらにしても
  **並び順は完全に一致**します。変わるのは表示値だけです（ステラミラクル 32.2%→47.5%）。
  「最高値を基準に何割取り逃すか」を見せる現行の定義を維持します。

なお、`batch_update` に入れるサブリクエストは73行で80件ですが、これは1回のAPIコールです。
Sheetsのクォータはコール数で数えるため、1実行あたり約20コールの現状に余裕があります。
サブリクエスト数を理由に書式の作りを変える必要はありません。

## 2026-08-18: 更新履歴の過去行を新しい列定義へ補正する

C列（比較行）は、旧仕様では単独掲載を含む全件、新仕様では2サイト以上の件数です。
このままでは過去行と最新行で意味が違い、履歴をグラフ化すると段差が出ます。

補正に外部データは要りません。旧行にも3サイト一致（D列）と2サイト一致（E列）があるので、
`1サイトのみ = 旧C - D - E`、`新C = D + E` で厳密に復元できます。
生成CSVは毎回上書きされるため過去分は残っていませんが、履歴シートの行だけで完結します。

補正は `publish_frames` に組み込み、G列が空の行を見つけたときだけ書き戻します。
一度補正した行はG列が埋まるので次回以降は対象外になり、繰り返し実行しても安全です。
ワンオフスクリプトにしなかったのは、更新をVercelページ経由で行っており、
ローカルにシートIDと認証JSONの環境変数を用意しなくて済むためです。
`旧C - D - E` が負になる行は補正せず、人が確認できるよう残します。

## 2026-08-18: サマリーへ書き込むのはA3:B8だけにする

「1サイトのみ」を足したときにカウンターが7項目になり、A9の結合リンクを避けて
取得エラーをA11へ逃がしました。これが誤りでした。A11には手で作った「取得元／URL」表の
collect行があり、上書きしてしまいました。リポジトリのコードはこの表を生成していないため、
差分にも現れず気づけませんでした。

対策として、このスクリプトがサマリーへ書くのは**A1とA3:B8とA9のリンクだけ**に固定します。
A9より下は人が管理する領域として触りません。7項目を6行へ収めるため、
3サイト一致と2サイト一致は「内訳（3サイト／2サイト）」の1行にまとめ、
取得エラーは元のA8へ戻します。

教訓は、コードが生成していないシート領域は差分に出ないので、
書き込み先を増やすときは実物を確認するということです。

## 2026-08-18: サマリーの参照をLOOKUPからMATCHへ変える

カウンターが数値ではなく更新履歴の列名（「比較行（2サイト以上）」など）を表示していました。
`LOOKUP(2,1/(更新履歴!A:A<>""),更新履歴!B:B)` は検索ベクトルが昇順である前提の書き方で、
列全体を参照すると残りがエラーで埋まります。これが見出し行に解決していました。

`INDEX(更新履歴!B:B,MATCH(MAX(更新履歴!A2:A),更新履歴!A:A,0))` へ置き換えます。
最終更新と同じ「最新の実行日時の行」を全カウンターが参照するので、
表示が互いに食い違いません。空行や並びの前提も不要です。

## 価格推移の横型マトリクス化と比較・履歴の視認性改善

日次更新の蓄積に伴い、「価格推移（シュリンク有）」の縦積み履歴が3,000行超・浮動グラフ87個まで肥大化し、人間が目視で相場変化を追うのが困難になりました。また、一部店舗が`状態不明`で同名BOXを掲載した際に`condition_inferred`フラグによって明示的なシュリンク有価格まで推移記録から除外される問題や、`SV8a`・`S12a`等の品番による名寄せ分裂が発生していました。

これに対し、データ保全と人間の視認性を両立するため次の構成へ変更します。

- **価格推移の2層分離（表示用マトリクス＋非表示アーカイブ）**:
  - 全期間の日次データ（`日付／商品名／最高値／最高値の店`）は非表示シート「推移データ（保管用）」に欠損なく蓄積します（既存の縦積み履歴も初回実行時に自動移行し、名寄せ後の商品名で統合します）。
  - 利用者が開く「価格推移（シュリンク有）」は**1商品1行**の横型マトリクス（`商品名／最新最高値／最高値の店／前回比／7日前比／30日推移／直近最大30回分の日付列（新しい順）`）とし、セル内`SPARKLINE`で左（古）→右（新）のミニグラフを描画します。並び順は直近で価格が動いた商品を最上段に配置します。
  - シュリンク有の最高値集計は、`raw`の明示的な`shrink_wrapped`行から直接算出することで、他店の`状態不明`掲載によって推移が途切れないようにします。
- **比較タブへの「前回比」追加と装飾改善**:
  - 比較タブを11列（`商品名／状態／最高値／前回比／最高値の店／差率／差額／コレクト／runto／買取ソムリエ／注意`）とし、上昇は緑太字・下落は青太字・横ばいは薄灰で表示します。全シートに1行おきのゼブラ配色・適切な行高・余剰空白行のトリミングを適用し、タブ順を`サマリー → 比較 → 価格推移（シュリンク有） → 単独掲載 → 更新履歴 → 全取得`に統一します。
- **更新履歴の降順化**:
  - 最新の実行結果を開いてすぐ2行目で確認できるよう、新しい順（降順、最大365件保持）で整列します。サマリー側の`MATCH(MAX(更新履歴!A2:A),更新履歴!A:A,0)`は並び順に依存しないためそのまま整合します。
- **名寄せの拡充**:
  - 品番除去を`SV`・`SM`・`S`・`M`系（`SV8a`、`S12a`等）へ広げ、`ソード & シールド`や`ソード シールド`のような空白・記号揺れ、`ポケモン GO`、ポケモンセンタースペシャルBOX、デラックスBOXの表記揺れを統一します。
