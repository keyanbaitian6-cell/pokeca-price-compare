# 判断記録

このファイルは、ポケカ買取価格表の対象サイト、名寄せ、更新方法、運用上の判断を記録します。
後日同じ調査を繰り返さずに済むよう、判断時点と再検討条件を併記します。

## 2026-08-18: 取得対象を3サイトとする

取得対象は次の3サイトです。

- コレクトの公開Googleスプレッドシート（読み取り専用）
- [runto](https://runto666.com/product-category/card/)
- [買取ソムリエ（ポケモンカード）](https://somurie-kaitori.com/products?category=2&subcategory=7)

コレクトの参照元シートには絶対に書き込みません。出力先の価格表は別のGoogleスプレッドシートです。

買取ソムリエの取得件数が7件なのは取りこぼしではありません。判断時点では対象ページ自体が
「1〜7件（全7件）」と表示しており、次ページも存在しませんでした。
[ポケモンカード・その他](https://somurie-kaitori.com/products?category=2&subcategory=13) は0件でしたが、
将来商品が追加される可能性を考慮して取得対象に残します。

### ARK TRADING CARDを追加しない

対象は[ARK TRADING CARD](https://arc-trading-card.jp)（宮城県仙台市）です。
[公式Xアカウント](https://x.com/arc_t_card)も調査対象にしました。

結論は見送りです。技術的に取得しにくいからではなく、判断時点でポケモンカード未開封BOXの
買取価格表そのものが公開されておらず、取得対象となる情報が存在しなかったためです。

調査内容は次のとおりです。

1. トップページのナビゲーション12項目に買取価格表に相当するページがありませんでした。
2. 「ギャラリー」は買取実績3件の掲載で、価格表ではありませんでした。
3. `/pokemon_card/`、`/news/`、`/sitemap/`、`/one_piece_card/lp10/` は直接HTTP取得で404でした。
4. 検索エンジンにはトップページ以外がほとんど索引されていませんでした。
5. 最終的にブラウザで目視し、買取価格が掲載されていないことを確認しました。

次のいずれかが確認できた場合に再検討します。

- サイト上に未開封BOXの買取価格一覧が新設された
- Xで買取価格がテキスト形式で継続的に告知されるようになった

画像だけの告知はOCRが必要になり、現在の個人利用に対して保守コストが見合わないため対象外です。
この判断は2026-08-18時点のサイト状態に基づきます。

## 2026-08-18: 未開封BOXの名寄せ方針

店舗ごとの表記差を吸収するため、商品名にはUnicode NFKC正規化を適用してから不要語を除去します。
部分一致による削りすぎを防ぐため、長い語から順に処理します。

主な除去対象は次のとおりです。

- 商品接頭辞: `ポケモンカードゲーム`、`ポケモンカード`
- シリーズ名: `スカーレット&バイオレット`、`ソード&シールド`、`サン&ムーン`、`ダイヤモンド&パール`、`XY BREAK`、`XY`
- 販売上の注記: `着払い対象外商品`、`着払い対象外`
- 状態語: シュリンクの有無、ぺりぺりの有無、`ボックス`、`BOX`
- 品番: `M3`、`M5`、`M1L`など。ただし独立した品番として現れた場合だけ除去する

`ポケモンカード151`は`151`へ寄せますが、`151 カードファイルセット`は別商品として維持します。
また、`ポケモンカードe 基本 海からの風`の`e`はシリーズ識別に必要なので削除しません。
`シャイニートレジャー`は`シャイニートレジャーex`へ寄せる既存の別名処理を維持します。

状態は商品名とは別に保持し、利用者向けシートでは
`シュリンク有`、`シュリンク無`、`ぺりぺり無`、`状態不明`、`未開封（状態不明）`と日本語表示します。
片方の店舗だけ状態不明の場合は比較を許可しますが、`一部店舗で状態不明`と明示します。
両方の店舗に実状態がある場合、シュリンク有とシュリンク無は別商品として扱います。

## 2026-08-18: 必要なときだけ手動更新する

毎日12時の自動更新は採用しません。価格表は利用者が必要なときだけ、
[Vercelの手動更新ページ](https://pokeca-price-update.vercel.app)から更新します。
Googleシートの「サマリー」にも同じページへのリンクを置きます。

手動更新ページは合言葉を検証した後、GitHub Actionsの`manual-update.yml`を`main`ブランチで起動します。
連続実行を避けるため、直近の実行開始から5分間、または更新処理の実行中は新しい起動を受け付けません。
定期実行のスケジュールは設定しません。

合言葉の平文、合言葉ハッシュ、GitHubトークンはフロントエンドとGitリポジトリに保存しません。
合言葉ハッシュとGitHubトークンはVercelのSensitive環境変数として保存します。
この判断記録にも合言葉の値は残しません。

### セキュリティ上の残存リスクを受容する

この更新ページは公開サービスではなく、URLを公開せず、利用者1名が約3日に1回使用する前提です。
通常運用は月約10回で、実測約2分のジョブをGitHubの分単位切り上げで1回3分と見積もると、
GitHub Actionsは約30分/月です。

2026-08-18の調査では、runtoへの1回の更新は一覧9ページと商品詳細32ページの計41 GETでした。
月10回なら約410 GET/月です。買取ソムリエは2カテゴリを開くため、最低20ページ遷移/月に
JavaScriptなどのサブリクエストが加わります。この頻度なら個人利用として許容できる負荷と判断しました。

現在の5分制限は、正しい合言葉による実行後の連続起動を抑止するものです。
失敗した合言葉の試行回数制限や、複数リクエストを原子的に処理する分散ロックは実装していません。
非公開URL、単独利用、低頻度という運用条件を前提に、この残存リスクを認識したうえで受容します。
URLを共有する、利用者を増やす、更新頻度を上げる、または公開サービスへ変更する場合は、
合言葉の強化、失敗回数制限、原子的なレート制限を再検討します。
