# 【購入者限定特典】生成AIカスタマイズプロンプト集（API課金0円・無料AI対応）

このプロンプト集は、**プログラミング経験がない方でも、手元の無料版／定額版の生成AI（ChatGPT / Gemini / Claude のWebチャット画面）にコピペするだけ**で、このキットを「自分の欲しいジャンル・自分の見たいサイト専用」に改造できるように設計した実用レシピ集です。

> **APIキー・追加課金は一切不要です。**  
> OpenAI API や Claude API などの有料APIキーを取得する必要はありません。普段スマホやPCで使っている無料チャット画面に、以下のプロンプトをそのまま貼り付けてお使いください。

---

## 使う前の 2 つのルール（必読）

### ルール①：AIチャットに「絶対に貼ってはいけないもの」
以下の秘密情報は、AIのチャット欄に **絶対に貼り付けないでください**。
- Google サービスアカウントの認証JSONファイルの中身（`private_key` 等）
- GitHub パーソナルアクセストークン（`github_pat_...` 等）
- スマホ手動更新の合言葉
- ログイン後のマイページや個人情報を含むHTML

### ルール②：対象ページのHTMLを 30 秒で取り出す手順（Chrome / Edge）
AIにサイト構造を教えるとき、URLだけ渡すよりも **「商品1〜2個分のHTML部品」を貼る方が精度が 10 倍上がります**。

```text
1. パソコンの Chrome（または Edge）で、監視したい公開ページを開く
2. 商品名や価格の上で「右クリック」→「検証（Inspect）」をクリック
3. 画面右（または下）に HTML コードが開くので、商品カード1つ分を囲むタグ
   （例: <article ...> や <div class="product-card"> や <tr>）にマウスを合わせる
   ※ 画面上で商品1つ分が青くハイライトされるタグを選ぶのがコツ！
4. そのタグの上で「右クリック」→「Copy（コピー）」→「Copy outerHTML（outerHTMLをコピー）」
5. そのまま下のプロンプトの【HTML抜粋】欄に貼り付けるだけ！
```

> **豆知識（JSON-LDチェック）**: ページの何もない所で「右クリック → ページのソースを表示」を開き、`Ctrl + F`（Macは `Cmd + F`）で `ld+json` を検索して `"@type":"Product"` が見つかれば、CSSセレクタ設定すら不要で `"type": "json_ld"` を選ぶだけで動く可能性が高いです！

## プロンプト 1：HTMLを貼るだけで `config.json` のサイト設定を自動生成する

**こんなときに使う**: 監視したい公開サイトを新しく `config.json` の `sources` に追加したいとき（コード記述ゼロ）。

```text
あなたは Python（BeautifulSoup4）と CSSセレクタに精通したエンジニアです。
以下の「価格監視ツール用 config.json の仕様」に従い、私が貼り付ける公開ページの HTML 抜粋から、`sources` 配列に追加する JSON ブロックを 1 つ作成してください。

【厳守ルール】
- 出力はそのまま config.json の sources 配列にコピペできる正しい JSON ブロックにすること
- ログイン回避や Bot 対策突破は行わないこと
- まずページが一覧ページ（複数商品が並ぶ）なら type="html_list"、個別商品ページなら type="html_single" を選ぶこと
- HTML 内に <script type="application/ld+json"> の Product 情報がある場合は type="json_ld" も提案すること
- 壊れにくい簡潔な CSS セレクタ（nth-child の多用を避け、クラス名や意味のあるタグ優先）を使うこと
- 最後に「どの要素が商品名・価格・状態・在庫にマッチするか」を初心者向けに3行で解説すること

【config.json の sources 仕様】
{
  "id": "半角英数字とアンダースコアのID（例: my_shop_a）",
  "label": "スプレッドシートに表示する店舗名（日本語OK）",
  "enabled": true,
  "type": "html_list または html_single または json_ld",
  "url": "監視対象ページのURL（html_singleで複数URLなら urls: [...] を使う）",
  "default_condition": "新品 / 中古 / 標準 など",
  "selectors": {
    "item": "（html_listのみ）1商品を囲む親要素のCSSセレクタ",
    "name": "商品名のCSSセレクタ",
    "price": "価格のCSSセレクタ",
    "condition": "（あれば）状態のCSSセレクタ、なければ空文字",
    "stock": "（あれば）在庫表示のCSSセレクタ、なければ空文字",
    "link": "（あれば）商品リンク(aタグ)のCSSセレクタ",
    "next_page": "（任意）次ページリンクのaタグセレクタ"
  },
  "stock_out_keywords": ["売り切れ", "在庫なし", "SOLD OUT"]
}

【私が監視したいサイト情報】
- 店舗名（任意）: （ここに記入 例：〇〇家電オンライン）
- 対象URL: （ここに公開ページURLを記入）
- ページ種類: （一覧ページ / 個別商品ページ）
- 比較したい目的: （安く買いたい / 高く売りたい）

【HTML抜粋（商品1〜2個分の outerHTML）】
（ここに右クリック→Copy outerHTML でコピーしたHTMLを貼り付け）
```

## プロンプト 2：複雑なページ専用の `custom_collectors/*.py` をAIに書いてもらう

**こんなときに使う**: 1つの商品カードの中に複数価格（新品・中古・サイズ別など）がある、テーブル構造が特殊、価格の単位が「万円」や「税込・税抜併記」など、`config.json` だけでは取り切れない公開ページを対応させたいとき。

```text
あなたは Python エンジニアです。
私が使っている価格監視キットのプラグイン仕様に合わせて、`custom_collectors/〇〇.py` の完全な Python コードを書いてください。

【絶対に守る仕様（インターフェース）】
- 依存ライブラリは Python 標準ライブラリと `beautifulsoup4` のみ使用すること（有料API・外部課金ツール・Playwrightは使わない）
- HTTP通信は必ず引数で渡される `client.fetch_text(url)` を使うこと（待機時間・robots.txt確認・リトライが自動適用されるため、`requests.get` を直接呼ばないこと）
- 関数シグネチャは厳密に以下にすること:
  ```python
  from __future__ import annotations
  from bs4 import BeautifulSoup
  from price_monitor.config import AppConfig, SourceConfig
  from price_monitor.http_client import PoliteHttpClient
  from price_monitor.models import PriceItem
  from price_monitor.normalize import normalize_name, parse_price_yen

  def collect(
      *,
      source: SourceConfig,
      config: AppConfig,
      client: PoliteHttpClient,
      fetched_at: str,
  ) -> list[PriceItem]:
  ```
- `PriceItem` のフィールドは次の通り:
  `source_id`, `source_label`, `name_raw`, `name_normalized`, `condition`, `price_yen` (int | None), `stock_status` ("available" | "out_of_stock" | "unknown"), `url`, `fetched_at`, `note`
- 最後に `config.json` の `sources` 配列に追加する設定例（`"type": "custom"`, `"collector": "ファイル名"`）も併記すること

【やりたいこと・特殊な条件】
- ファイル名: `custom_collectors/（例: camera_shop_x）.py`
- 対象URL: （公開ページのURL）
- 特殊な条件: （例：価格は「12.8万円」表記なので円に変換したい / AランクとBランクの2行に分けて抽出したい / 税込価格の方だけを取りたい）

【HTML抜粋】
（ここにCopy outerHTMLで取ったHTMLを貼り付け）
```

## プロンプト 3：複数サイトの「表記揺れ・名寄せルール」を一括自動作成する

**こんなときに使う**: 実行してみたら、同じ商品なのに店舗Aと店舗Bで商品名が微妙に違って「単独掲載」に分かれてしまったとき。

> **コツ**: `data/raw_prices.csv`（またはGoogleシートの「全取得」タブ）から「取得元」と「商品名（原文）」の列を20〜100行ほどコピーして下に貼るだけです！

```text

同じ商品なのに表記揺れで別扱いになっているものを自動で1行にまとめるため、
`config.json` の `normalization` セクション（`strip_phrases`, `strip_regex`, `aliases`）を作成してください。

【出力条件】
1. どの店舗でも邪魔になる装飾語（例: 【送料無料】、【新品】、税込、型番ノイズ等）は `strip_phrases` または `strip_regex` に入れること
2. 略称や表記揺れ（例: "GR3" → "RICOH GR III"、"Switch 有機EL" → "Nintendo Switch 有機ELモデル"）は `aliases` に入れること
3. ただし「別商品・別モデル・別カラー・容量違い（128GB vs 256GB 等）」まで誤って統合しないよう慎重に判断すること
4. 出力はそのまま `config.json` の `"normalization": { ... }` にコピペできる JSON 形式で出力し、最後に「統合されるペア一覧」を表形式でチェックさせてください

【取得元と商品名（原文）のリスト】
（ここに raw_prices.csv または「全取得」タブからコピーした内容を貼り付け）

```text

この `notifier.py` の `should_send_notification` と `build_notification_message` を拡張して、次の条件を追加してください。

【追加したい通知条件】
（例1：差率 15% 以上の掘り出し物が見つかったときも通知する）
（例2：前回の `data/raw_prices.csv` と比べて「在庫切れ → 在庫あり」に復活した商品があれば最優先で通知する）

## 付録：ジャンル別おすすめ設計レシピ 5 選

どれから作ろうか迷ったら、以下の設定パターンを参考にしてください（`config.examples/` に雛形も入っています）。

| ジャンル | 推奨モード | 監視のコツ | おすすめ目標アラート設定 |
| --- | --- | --- | --- |
| **① 家電・PC・ガジェット** | `lowest`（最安） | 欲しい型番 3〜10 商品に絞り、`json_ld` または `html_single` で個別ページ監視 | 普段価格の 10〜15% オフを目標価格にセット |
| **② スニーカー・限定アパレル** | `lowest`（最安） | 在庫切れキーワード（`SOLD OUT` / `入荷待ち`）を必ず設定し、再入荷＆値下げを検知 | 定価以下、またはプレ値上限ラインを目標設定 |
| **③ レトロゲーム・中古カメラ** | `highest`（買取）または `lowest`（中古購入） | 状態（美品・並品・箱説付）を `condition` に分けて混ぜないようにする | 手持ちアイテムの「この額なら売る」ラインを設定 |
| **④ 推し活グッズ・フィギュア** | `lowest`（最安） | 予約店・中古ショップの公開一覧を `html_list` で監視し、`aliases` でキャラ名表記揺れ統一 | 定価・送料込の予算上限を目標設定 |
| **⑤ 日用品・ふるさと納税・消耗品** | `lowest`（最安） | 定番リピート品（コーヒー豆・プロテイン・おむつ等）の公開ページを毎日 1 回チェック | いつもの底値（例：1kg 2,980円）を目標設定 |
