# 初回ヒアリングシート＆要件ズレ・無制限修正防止チェックリスト

ミニ受託（1〜5万円）で赤字になる最大の原因は、**「対象URLや出力列が曖昧なまま着手し、納品後に『あの項目も欲しい』『このサイトも足して』が無限に発生すること」**です。
このシートを着手前に必ず埋め、クライアントとテキスト上で合意（言質）を取ってから実装に入ります。

## 3. 受注者側（自分用）地雷回避チェックリスト（着手前に全項目確認）

| # | 確認項目 | NGだった場合の対処 |
| :-: | --- | --- |
| 1 | 対象URLはログイン不要・公開ページか？ | ログイン必須・個人情報系は辞退（規約・法的リスク大） |
| 2 | Cloudflare Turnstile / reCAPTCHA / 厳格WAFが出ていないか？ | CAPTCHA突破は厳禁。事前調査で検知したら必ず辞退 |
| 3 | `robots.txt` と利用規約で自動収集が明確に禁止されていないか？ | 禁止明記サイトは辞退し、公式APIや別ソースを提案 |
| 4 | 1回の巡回ページ数は妥当か？（目安：50〜100ページ以内、1秒間隔で数分以内） | 1万ページ規模は1〜5万円の枠外。カテゴリ絞り込みか高額カスタムへ |
| 5 | 取得項目が「画像の中に文字で書かれている（OCR必須）」ではないか？ | 画像OCRは保守不能・精度トラブルの温床。対象外と明言 |
| 6 | 出力シートにクライアントが手入力している領域がないか？ | 手入力セルがある場合は「絶対に上書きしない範囲」を事前に固定 |
| 7 | 名寄せの例外パターンが多すぎないか？（商品数500超×独自略称だらけ等） | 初期は「代表的な表記ルール＋手動修正用の別名辞書（CSV/定数）提供」で合意 |
| 8 | 認証情報（GoogleサービスアカウントJSON・GitHub PAT・合言葉）の扱いを確認したか？ | チャットに平文で長期放置しない。お客様側のSecretsへ直接登録する手順で進める |
