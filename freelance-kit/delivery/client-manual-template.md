## 2. 普段の使い方（Googleスプレッドシートの見方）

普段の業務では、**Googleスプレッドシートを開くだけ**で最新データを確認できます。プログラムやGitHub画面を操作する必要はありません。

### 各タブの役割

| タブ名 | 内容・見るポイント |
| --- | --- |
| **サマリー** | 最終更新日時・取得件数・比較件数・エラー件数を一目で確認できます。（※`{{MANUAL_CELL_AREA}}` 以下のお客様メモ欄は自動更新で上書きされません） |
| **比較** | 2サイト以上に掲載がある商品を「差率の大きい順」に表示します。 |
| **価格推移（30日）** ※導入時 | 1商品1行で最新値・前回比・7日前比・30日ミニグラフ（SPARKLINE）を表示します。直近で価格が動いた商品が最上段に並びます。 |
| **単独掲載** | 1サイトのみに掲載されている商品を分離して表示します。 |
| **更新履歴** | 実行日時・取得件数・エラー数を**新しい順（2行目が最新）**で最大365回分記録します。 |
| **全取得** | サイト原文の商品名・URLを含む全レコードの確認用タブです。 |

### 色分け・強調ルールの意味
- **緑色の背景セル**：対象商品の中で最も有利な価格（最安値または最高買取値）
- **赤色の太字（差率列）**：価格差率が `{{RATE_THRESHOLD}}`（例：5%）以上
- **金色の太字（差額列）**：価格差額が `{{YEN_THRESHOLD}}`（例：¥3,000）以上（高額商品で見落としを防ぐため独立強調）
- **前回比の緑／青**：前回更新時より上昇は緑、下落は青、横ばいは薄灰
- **薄黄色のセル（注意列）**：一部店舗で状態記載が省略されたため補完比較した行（`状態推定`）など

### スマホ1タップ手動更新の使い方（※オプション導入時）
1. 専用更新ページ（`{{MANUAL_UPDATE_URL}}`）をスマホのブラウザで開き、ホーム画面に追加します（GoogleやGitHubへのログインは不要です）。
2. 設定した「合言葉」を入力し、**「最新データを更新する」**をタップします。
3. 「更新を受け付けました」と表示されれば起動完了です。通常 **2〜5分程度** でスプレッドシートへ最新値が反映されます。
   - ※連続実行による負荷防止のため、更新開始後 **5分間** は再実行がブロックされます。

## 3. 初回セットアップ手順（納品時の初期設定）

### ステップ1：出力先Googleスプレッドシートの準備
1. ご自身のGoogleドライブで新しいスプレッドシートを作成します。
2. ブラウザのURL欄 `https://docs.google.com/spreadsheets/d/【ここがシートID】/edit` から **スプレッドシートID** を控えます。

### ステップ2：Google Cloud でサービスアカウントを作成（無料）
1. [Google Cloud Console](https://console.cloud.google.com/) で新規プロジェクトを作成します。
2. 左メニュー **「APIとサービス → ライブラリ」** から以下2つを検索して **有効化** します。
   - `Google Sheets API`
   - `Google Drive API`
3. **「IAMと管理 → サービスアカウント → サービスアカウントを作成」** で任意のアカウントを作成します。
4. 作成したサービスアカウントの **「キー → 鍵を追加 → 新しい鍵を作成 → JSON」** を選び、JSONファイルをPCへダウンロードします。
5. 作成したサービスアカウントのメールアドレス（`xxx@xxx.iam.gserviceaccount.com`）をコピーし、ステップ1のGoogleスプレッドシートの **「共有」から「編集者」として追加** します。

### ステップ3：GitHubリポジトリへ秘密情報を登録
1. 納品されたお客様専用の **非公開（Private）GitHubリポジトリ**（`{{GITHUB_REPO_NAME}}`）を開きます。
2. 上部タブ **Settings → Secrets and variables → Actions → New repository secret** を開きます。
3. 以下の2つを登録します。

| Name（名前） | Secret（値） |
| --- | --- |
| `GOOGLE_CREDENTIALS_JSON` | ステップ2でダウンロードしたJSONファイルの中身全文 |
| `OUTPUT_SPREADSHEET_ID` | ステップ1で控えた出力先GoogleスプレッドシートID |

### ステップ4：初回テスト実行の確認
1. GitHubリポジトリの **Actions** タブを開き、`{{WORKFLOW_NAME}}` を選択します。
2. 右側の **Run workflow → Run workflow** をクリックします。
3. 2〜5分後に緑色のチェックマーク（Success）になり、Googleスプレッドシートの各タブにデータが入っていれば設置完了です！

### ステップ5：スマホ1タップ手動更新ページの設定（※オプション導入時のみ）
1. GitHubの **Settings → Developer settings → Personal access tokens → Fine-grained tokens** で新規トークンを発行します。
   - Repository access：`Only select repositories` → `{{GITHUB_REPO_NAME}}` のみ
   - Repository permissions：`Actions` を **Read and write** に設定
   - 有効期限：管理できる期間（例：90日〜1年）を設定し、カレンダーに更新リマインダーを登録してください。
2. 合言葉のSHA-256ハッシュ文字列を生成します（納品時に安全な生成方法をご案内します）。
3. **Cloudflare Pages（商用利用OK・無料枠）** へリポジトリを接続し、配信対象フォルダを指定のうえ、**Settings → Environment variables（Encrypted / Secret）** に以下を登録してデプロイします（※個人・非商用利用に限りVercel Hobby等も選択可能です）。
   - `GITHUB_TOKEN`：上記1で発行したトークン
   - `UPDATE_PASSWORD_HASH`：合言葉のSHA-256ハッシュ（64桁の16進文字列）

## 4. トラブルシューティング（困ったときの確認順）

### Q1. 決まった時間になってもシートが更新されない
1. GitHubリポジトリの **Actions** タブを開き、最新の実行履歴を確認してください。
   - **赤い「×」になっている場合**：対象サイトのメンテナンスやデザイン変更によりデータ保護ガード（0件上書き防止）が働いた可能性があります。該当ログを開いてエラー内容をご連絡ください。
   - **実行履歴自体が増えていない場合**：公開リポジトリで運用している場合、GitHub Actionsの仕様により60日間リポジトリ更新がないとスケジュール実行が一時停止することがあります（非公開リポジトリ推奨）。Actionsタブの **「Enable workflow」** ボタンを押すだけで即座に再開します。
2. なお、GitHub Actionsの定時実行は混雑時間帯に5〜20分ほど前後することがあります。

### Q2. スマホ手動更新ページでエラーが出る
- **「合言葉が違います」**：入力ミスまたは全角スペース混入がないかご確認ください。
- **「約◯分後にお試しください」**：5分以内の連打防止ガードが正常に働いています。少し待ってから再度お試しください。
- **「更新を開始できませんでした」**：ステップ5で発行したGitHubトークンの有効期限切れの可能性が高いです。GitHubでトークンを再発行し、環境変数 `GITHUB_TOKEN` を上書きして再デプロイしてください。

### Q3. 取得結果の一部商品が別行に分かれてしまった
- 対象サイト側で新表記・新シリーズ名が追加された場合に発生することがあります。`normalize.py` の別名辞書（`_PRODUCT_NAME_ALIASES`）へ1行追加するだけで解消できます。
